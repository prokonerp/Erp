# Deployment & Environment

## Deployment topology
- **Cloudflare Workers** — TanStack Start SSR app (worker name `tanstack-start-app`; `wrangler.jsonc`: compatibility `2025-09-24`, flags `["nodejs_compat"]`, main `src/server.ts`).
- **Supabase** — managed backend (`vimkodursmcsaptrrzbl`), schema via 138 migrations.
- **No in-repo CI/CD** — no `.github/`, no workflows. Deploys are driven externally (Lovable Cloud pipeline, per `.lovable/*` handshake files). Manual deploy would be `bun run build` (or wrangler) — see package.json scripts.

## Environment variables (names & roles — values live in `.env`, which is git-tracked!)

| Variable | Role |
|---|---|
| `SUPABASE_PROJECT_ID` | Supabase project ref (also in `supabase/config.toml`) |
| `SUPABASE_URL` | Supabase API URL (server-side / MCP use) |
| `SUPABASE_PUBLISHABLE_KEY` | Anon/publishable key (server-side / MCP fallback) |
| `VITE_SUPABASE_PROJECT_ID` | Project ref exposed to client bundle |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key exposed to client bundle (browser client) |
| `VITE_SUPABASE_URL` | URL exposed to client bundle |
| `SUPABASE_SERVICE_ROLE_KEY` | **Service role key — bypasses RLS. Server-side only** (`client.server.ts`, HMAC secret for public uploads, MCP key parsing). Never in client code. |
| `SUPABASE_PUBLISHABLE_KEYS` | (optional) JSON key-set for MCP per-request clients |

Notes:
- `.env` currently holds the ORIGINAL project's live credentials and is **tracked in git** (was committed in the original repo). It is NOT in `.gitignore`. **Decision pending from project owner: keep as-is (they will update later) — flag for rotation/untracking before any public push.**
- Cloudflare secrets (`.dev.vars`, wrangler vars) are gitignored / injected at deploy time — not committed.

## Build & run
- Package manager: **Bun** (`bun.lock`). Run `bun install`, `bun run dev`, `bun run build` (see package.json scripts for exact names).
- Build output targets Cloudflare Worker (`dist`); `nodejs_compat` flag required.

## Lovable specifics
- `.lovable/project.json` — template `tanstack_start_ts_2026-05-12`.
- `.lovable/mcp/manifest.json` — auto-generated by MCP plugin.
- `.lovable/plan.md` — historical plan for A4 print/PDF template (quotation + PO) — informational only.
- Do not hand-edit auto-generated Lovable files unless you know what you're doing (routeTree.gen.ts, .mcp routes, manifest).

## Supabase migrations workflow
- Schema changes: add new SQL file under `supabase/migrations/` with timestamp prefix (e.g., `20260821..._name.sql`).
- Existing migrations must not be edited after being applied to the live DB (138 files; live DB has additional drift — see `database.md`).
