The problem
PROKON ERP
Two leaks

Money walked out the door.
Parts never came home.

Custody leak

On every swap, the dispatched part stayed on the engineer's holding forever — the GRN cleared a row that was never stamped, and the real row leaked. "Material holding" was a growing fiction.

Money leak

Two Postgres lessons
PROKON ERP
Bought with real failures

The database kept its secrets
until we tested it.

Lesson 1
DEFINER blinds you

Inside SECURITY DEFINER, current_user is the function owner — a permission guard written there can never see authenticated and never fires. Guards must be SECURITY INVOKER. Proven on scratch.

Lesson 2
Grants add up

A table-level UPDATE grant authorizes every column — a later column REVOKE is a silent no-op. The trigger is the real lock; the revoke is decoration.

Both are now permanent engineering rules in project memory10 / 12
