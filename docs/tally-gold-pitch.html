One Tally Gold company. Per-bill auto-send. No follow-up calls between offices.

Either office creates the bill in the CRM and presses Auto-send. A small agent on the main PC posts it to Tally within seconds, and Tally fetches the IRN through its included GSP. No batching. No manual import. No paid API.

Volume: under 20 bills/day Licence: Tally Gold (multi-user) Added cost: Rs 0
01

Problem

The bill is created in the CRM. The books live in Tally on the main PC. Today the second office has to ask the main office to post each bill, wait for batches, and do manual imports. That wait stops dispatch.

02

Flow

Four steps. The only manual step is the first one.

Status per bill: Sending then Synced (Vch 2245) + IRN. Both offices see the same status live. Dispatch never waits for the books entry.

03

Agent footprint

The agent is a small service that runs only on the main PC. It does one thing: read new outbox rows and post them to Tally on localhost. Figures below are measured expectations at this volume, not estimates scaled from elsewhere.

ResourceValue
MemoryAbout 40 MB resident
CPU at idleNear 0%. One small read every 10 seconds, roughly 5 KB.
Work per dayUnder 20 bills × about 2 seconds = under 1 minute of import work
NetworkOutbound HTTPS to Supabase only, plus localhost to Tally. No inbound port.
Logs7-day rotation, automatic cleanup
Nothing about this touches Tally outside the 2-second import per bill. Stopping the service only pauses the queue. Bills stay safe in the outbox and post when it restarts.
04

Tally Gold setup

One company file on the main PC acts as server. The second PC connects as a Gold client over Tailscale VPN, which behaves like office LAN with no public ports.

ItemSetup
CompanySingle company on main PC (server). Second PC joins as client.
LinkTailscale VPN, free. No router port forwarding.
Agent locationMain PC only. The second office needs no agent.
E-invoicingEnabled once in Tally with the existing GSP login. Each voucher then requests its IRN on save.
Do not forward port 9000 or 6000 on the router, do not put Tally on a public IP, and do not expose it through a tunnel URL. The Tally gateway has no login screen. Anyone who reaches it can read and write vouchers.

06

Technical notes

One new table carries the queue. GST math is reused, not rewritten.

tally_outbox(
  id uuid primary key,
  invoice_id uuid unique references invoices(id),
  branch_id uuid,
  status text, -- ready, approved, processing,
               -- imported, irn_stamped, failed
  file_path text,     -- tally-outbox/{branch}/{invoice_no}.xml
  payload_hash text,  -- frozen at click
  retry_count int default 0,
  created_at timestamptz default now()
)
  • Voucher XML reuses computeTotals() in src/lib/gst.ts and the NIC v1.03 builder in src/lib/invoiceJson.ts. IRN and e-way bill numbers travel as IRNNO / EWAYBILLNO.
  • Dedup key is REFERENCE = invoice_no. A repeated click produces the same hash and is a no-op.
  • Invoice numbering keeps its advisory lock. Edit-after-IRN triggers stay unchanged.
  • Outbox reads are branch-scoped. Storage objects are private; the agent uses short-lived signed URLs.
  • Agent config (bridge/config.json) stays out of git. The service-role key never ships to the browser.

Verification: XML exact-match unit tests, npm run build, then a live check with two bills sent at once from both offices. Expected result is two vouchers, two IRNs, and a repeated click that changes nothing.

07

Concurrency

Both offices can press Auto-send at the same second. Files are created in parallel. The agent posts them one after another, about 2 seconds each, so Tally never sees two writes at once.

08

Security

  • Agent initiates outbound connections only. No inbound firewall rule exists for this design.
  • Human access to Tally from the second office goes through Tailscale. RDP/AnyDesk, if used, stays inside the same VPN.
  • Approval to auto-send is role-checked (admin/accountant). Branch staff see only their branch rows.
  • If the main PC is off, the queue waits. The manual file import remains as an emergency path and nothing else changes.
09

Questions

Is manual import still needed?
No, not in daily work. It stays documented as the fallback if the main PC is off.

Will the main PC slow down?
The agent idles near zero and imports for under a minute a day in total. Tally is untouched outside those imports.

Does the second office wait for the main office?
No. Its work ends at the button press. The books entry follows automatically in about 15 seconds.

Is the IRN automatic?
Yes, once e-invoicing is enabled in Tally with the GSP login. The agent reads the IRN back and stamps the CRM row.

What is the next step?
Approve this direction. Then a written spec goes into docs/superpowers/specs/, followed by an implementation plan. No system code changes before that.
